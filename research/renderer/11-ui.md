# renderer/11-ui: UI quad render path, glyph atlas, vertex upload, FG HUD-less path (package 11, 2026-10-10)

Static pass over `<re-scratch>\decomp` plus `ui-mainthread.md`, `post.md`, `12-capture-check.md` and `05-frame-graph.md`. Game not run. Tags: **M** measured / confirmed by FCAP1, **S** read in the C export, **?** inferred.
`ui-mainthread.md` holds the byte-level patch designs (W1b, E, C, R); this note is the renderer-side picture and the keep / replace verdict.

## 1. Where UI sits

- Graph node **StaticScreenLayout** (hash 0x48570415, nodes **418 and 424**, vtable 40EAF20, Execute = **UiViewRender 253C68**, ctor 3451798 via factory 25B55E4). Level L23 with `OffScreenRendering` (nodes 417-424) **M**.
- It is after PostEffectApply and FSR3, at **output resolution** (1920x1080 in the captures): the UI never goes through the upscaler `05` / `post.md`. FCAP1: `OffScreenRendering` 44-108 draws at 1920x1080, a 3840x3240 BGRA8 offscreen target, 64x64 glyph / mask targets, then `VideoOut` (1 draw) **M** (`12-capture-check.md` G12).
- The shader family is `AMBSL` (the UI quad shader; **not** ambient lighting, `lighting.md` §2). GP2 cost: 0.267 ms before the VRAM-streaming fix, 0.110 ms after (`root-cause-vram-streaming.md`).
- Other UI nodes: `SSFadeSaturation` (SSFadeSaturationNodeExecute 927DF8, 418 B) for the screen fade / desaturation; the FFX UI resource and the HUD-less colour (§4).

## 2. CPU path (per frame, render main thread) **S**

```
UiViewRender 253C68 (1.4 KB, StaticScreenLayout Execute)
  KtglCmdStreamFlush                         (cuts the list before UI: UI starts a fresh stream segment)
  view = (node+1F8 >> 24 & 7F) + (R+974 & 7FFFFFFF); bail if >= 32 or sc+180[view] == 0
  if mode != 1 (mode = node+1F8 & 0xF):
      SaveColorBeforeUiRendering 3453364     (copy HUD-less colour; FG, §4)
      RenderUiMask 3453134                   (CGraphicsDevice::m_pUIMask, for FG UI compositing)
      UiBeginSeparateUiTarget 3451a94        (separate UI target, with UiEndSeparateUiTarget 34529BC)
  "OffScreenRendering" event (R vfn+58)      (mode 0)
      StaticScreenLayoutOffScreenBegin 34521CC
      for each offscreen entry (type 3 / 4 list at view+4370): StaticScreenLayoutOffScreenEntry 3451BE0
  UiTextFrame 254440  (the glyph / text-layer part, §3)
  ... then the UI element walk (UiRenderPathEntry 7D61A8 -> UiRenderPath 7D622C -> UiDrawLayer 1C0FFC)
```

- `UiRenderPath` 7D622C (305 B) calls `UiWalkLayer` 7D63E4 (370 B, rasterize = 0, **a no-op walk** over every element, `ui-mainthread.md` R) and then **UiDrawLayer 1C0FFC** (920 B): `UiDrawLayerPrepareIcons` 1CD1E4, **`UiQuadBuild` 1CD690** (811 B) and the draw.
- `UiRasterizePath` 30DDD18 (318 B) is the rasterize=1 twin used from the text path (`UiWalkLayer` with rasterize=1 -> `UiElementWalk` 1CE818 -> glyph decode).
- UI is a **retained element tree** (`UiElementWalk` 1CE818 with element types 2 and 9, widgets resolved by `UiElementResolveWidget` 1CEA08). It is rebuilt into vertex buffers every frame; there is no "unchanged" check (`ui-mainthread.md` "Not found").

**Vertex upload.** `UiQuadBuild` maps `[obj+378]` write-only (`GpuBufferMap` 4FD84 over an **upload heap**, which is write-combined memory) and `UiBufferPoolAcquire` 9261DC supplies a fresh ring buffer per frame. It builds quads and **does an alpha read-modify-write on the mapped (WC) memory** (cursor `[obj+358]`, capacity `[obj+394] - [obj+39C]`). Reading WC memory is uncached: ~2 ms on pc2 (the figure in `00-map.md`; the profiler share is 1.1-1.7 % of the main thread). Unmap (`GpuBufferUnmap` 4FBD4) then copies `[B+78]` bytes on the GPU from staging to the VB.

## 3. Glyph atlas **S**

- Glyph cache G: ctor 2EDAE7C (0x260C8 B): 64K x u16 code table at +B0, 1025 nodes x 0x18 at +200B0, capacity 1024 at +78, pad 1 at +7C, **persist flag +A8**. Created by 32FAE8C with 3 textures in a ring at G+18..40.
- Shelf packer in 62000 (x +84, shelf y +88, maxY +8C, W / H +90 / +94; key = code | page | palette). Overflow drops the rest of the frame's text with no retry.
- Per frame: `UiTextFrame` 254440 -> `UiAtlasMap` 30DD720 (staging map) -> `TextLayerRasterize` 7D6B20 for each of the 32 views x 2 layers (rasterize=1, decode + padding, `rep stosd` with count 1 = the W1b hot spot) -> `UiAtlasUpload` 30DE7E8 (-> `GlyphAtlasFlush` 4A2E44; uploads rect {0, 0, W, maxY}) -> clears `4A0`.
- **The atlas is wiped every frame (4A529C -> 96A2C0) although the persistent-atlas mode is on**, so every glyph is re-decoded and re-uploaded every frame (candidate C in `ui-mainthread.md`).

## 4. Frame generation / HUD-less path **S/M**

- With FG on, `SaveColorBeforeUiRendering` 3453364 copies the colour before UI into the HUD-less target (`CRenderer::m_pHudLessColor`), and `RenderUiMask` 3453134 renders `CGraphicsDevice::m_pUIMask`. The FFX UI resource (config type 0x30002) is registered so FG composites the UI over interpolated frames (`post.md` §9). The flags are `R+3DE69 / 3DE6A / 3DE6D` (cleared when the target is invalid) and sc-view `+25B0 / +2534 / +2524 / +25B1` (stage enable bytes).
- So the UI is rendered once per **real** frame; interpolated frames get the previous UI via the mask. A new renderer must keep: HUD-less colour copy before UI, the UI mask, and UI at output res into the swap chain's resource (or the FFX UI texture).

## 6. New renderer: keep / replace

- **Keep:** UI as an **overlay pass** at output resolution after post, fed by the UI element tree (the game side). Keep the FG hooks: HUD-less copy, UI mask and the optional separate UI target. These are cheap and the FG path depends on them.
- **Replace / cheap wins** (the percentages are estimated (E) shares of main-thread time, not measured fps gains; the main thread
  is not the limit on a GPU-bound machine):
  1. **Build quads in cached (WB) memory and stream-copy once** (candidate E): the vertex build would read nothing from WC. The gain is 1-1.5 % of the main thread; in a new submission layer the same effect comes free by allocating the VB write-only from a CPU-cached scratch.
  2. **Persistent glyph atlas** (candidate C): stop wiping; track dirty rows; upload only changed rows. 0.5-3 % of the main thread plus PCIe traffic.
  3. **Padding loop fix** (W1b): plain store loop in 61BAC, 1-2 %.
  4. **Skip the no-op walk** (R): 0.2-0.8 %.
  5. **Retain the vertex buffers when a layer is unchanged**: not detectable from the engine today; a new renderer that owns the UI draw lists could diff by layer.
  6. Fold the `OffScreenRendering` small draws (44-108 at 1080p) into the single UI target when the offscreen size matches (3840x3240 target looks like a 4K-class atlas; reducing it is a bandwidth win on the Ally).
- **Not worth replacing:** the GPU side (0.11 ms). The UI shaders are trivial; all cost is on the CPU upload path.
- **Questions:** the exact contents of the 3840x3240 offscreen (video / mask layers?) and the reason for the mode 0 / 1 split of node+1F8 (package 05 / game side); the owner of `R+3DE69..` HUD-less handles (post).
