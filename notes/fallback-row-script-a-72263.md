## Generic implementation

`tools/gen_native_entry_gates.py` joins every catalogue mission to its original script and selected enemy record. It follows only calls after a literal WaitWarpStart: named CALL_FN and decoded Script::Create string-pool edges. Acceptance requires either a selected literal Character::Create/CreateAndWait reachable in that graph or a WaveBattle::RequestID equal to the selected enemy record's u16+0x1A. It emits only a unique gate; multiple distinct linked gates are rejected. No boss, row or mission allowlist. Native prerequisites are preserved; graph reachability is not a claim that the live branch took that path.

The generator emits23 mission/placement/gate entries with full provenance in `notes/native-entry-gates-72263.json`. BR uses the generated dependency for Training-owned Fight now, including box gates and rows marked atFight by incomplete catalogue heuristics. Other paths retain the existing door rule. GateTick and RightsCheckHook still require the exact right actually polled by the mission script, active request ownership, matching mission, solo/offline, loaded player and no active fight. No story flags, temp writes, native Create calls, wave requests or BR movement were added. Training remains the mover.
