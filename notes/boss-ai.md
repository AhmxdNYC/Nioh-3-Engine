# Boss AI / behaviour data (static, game not run, 2026-10-08)

## Headline: there are no per-boss AI script files in the extracted archives
- Searched all of `data\extract` (root 97, stage 211, system 165, lfm archives 00-19) for bytecode scripts, AI/phase/grab strings and AI property hashes.
- Only 4 archives hold VM scripts (header `2011-04-29T14:26:48+0900`): archive_09 = 110 mission scripts (the boss fights), archive_14 = 321 and archive_16 = 132 **gadget/interaction/hell-door** scripts (Status/Motion/Interaction APIs, no boss logic), archive_05 = 2 **Groupthink** scripts.
- **archive_05** (`71/AB3A28..` 11.9 KB, `73/494DB4..` 7.9 KB): `script_NormalGroupThink` / `script_HardGroupThink`, vars `now_group_entry_num`, `battle_enemy_list_reset_count`. This is the crowd "who attacks now" coordinator (Groupthink::SetRole*, SortList*, IsCharacterWantToAttack, ExclusionFarAttackState ...), enemy-agnostic. 0 phases, binds to no character id.
- **Boss AI itself is the engine AIGraph system** (types `AIGraph` 0x919BBDE9, `AIGraphSettingBase`, `AIGraphExecuteHelper`, `MotorAISetting` 0x7AC0C15A; props `AIGraphObjDBHash`, `AIGraphAgentNameHash`, `AIGraphStateMachineNameHash`, `AIGraphHelperObjectNameHash`, blackboard get/set; see `data\tools\kassent_property.txt`). **None of these objects are in any ObjectDatabase**: a type scan of all 17,038 root ObjectDatabaseFile entries (typescan.py) found 0 AIGraph / MotorAISetting / AI objects. In `MotorCommonSetting` (root 0x6d011726) `AIKeyHashArray`, `AINameArray`, `AISettingObjectNameHashArray` are all empty. So AI graphs are compiled elsewhere (not ODB; likely packed in an RDB entry type we do not parse, or the executable's static data). Next step if wanted: search the 528 root `BinaryFile` and 584 `KSCLFile` entries and `Nioh3.dump.exe` for the AIGraph type hash.
- Enemy `MotorCharacterSetting` (2138, root 0x2082ad97) has only model/action/colour fields, no AI link. `CharacterSettingLoader` (1952 tiny ODBs) maps loader -> character setting only. The registry `CharacterNameArray` (2138) contains only cosmetics/gear (CC_*, CE_*, IW/IE, DR, ...), `C0000_HERO_0`, `C9000_HUMAN_COMMON`; **no readable enemy/boss names exist there**, so char ids cannot be tied to names via this table.
- Placement groups in archive_03 (1295 chapter/quest files, name table at file end) do carry readable boss tokens, e.g. `CH08_MAIN03_DOKANYAMA_{MARIA_FIRST,MARIA_SECOND,MITSUKUNI,JUBE,MIDDLE_BOSS_KUMAGAI,BOSS_SHOSETSU,NURIKABE,COOP_RODORIGO}`, `CH06_MAIN03_KIYOMIZU_ENEMY_BOSS`, `KITAN_22_BOSS`, `CH02_WORLD_SENGOKU_3_MAISAKA_BOSS`. The bodies are compressed/opaque so no id is bound yet; the bridge to char ids is still open.

## What does exist: the script-to-AI interface in the 110 boss mission scripts
Missions steer the native AI through a few C-APIs. `notes\boss-ai.csv` has one row per archive_09 script (key = first 12 hex of the file name, same as `boss-fights-table.csv`), library functions shared by >=15 scripts excluded (they otherwise flood every row):
- `Character::SetAIEventFlagForUnit(actor, n)` (36 scripts) and `...ForMission(.., n)` (7): event numbers sent to the boss AI (phase/cutscene/trigger cues). Common values: unit flags 85-122 (e.g. 110 in 8 scripts, 85, 91, 105, 111, 112, 113), mission flags 17,19,20,26,27,28,84,95 (the same 17/19/27/28 set in several scripts = a stock trigger group). Raw arg pairs are in columns `ai_event_*` as `placementId;flagNo`. `var` = non-constant.
- `Character::SetAIExtOrderFlag(actor, n)` (25 scripts): external order (6 appears to be the shared "off/clear" value: pairs like `id;6`).
- `Character::GetHpRate` (43 scripts, own functions) with float thresholds = **phase-change HP cut-offs** read in the script. `hp_thresholds` column; 1.0 is mostly "full HP" checks. Examples: B023D29AFD54 0.2/0.3/0.5/0.698/0.7/0.8/0.999 (7 stages: heaviest, ~6 phases, akaname/barrel/barrier tokens); 663667288B5D 0.2/0.4/0.7 plus `SetHpRate` 0.25/0.5/0.75 steps (blood, antigravity, bossbattle); 526F7C4E6488 0.5/0.8/0.85; 9B7E22C510B1 0.1/0.8/0.9; 0CA8409CACB7 (S90_DLC1, Hongo) 0.3/0.5; 2DB4694D793C (S03_KOD_01_REIJU) 0.2/0.5/0.9; 5F2E0518FFC8 (S04_BAK_03_HONNOJI) 0.6 with functions `bosschange..bosschange6`; 2B59B8417AAE 0.8; 45C15A1FFB1A 0.6; 8008F3E2B14D 0.35; 70D08AB4D345 (boshitsuki) 0.01.
- `Character::SetHpRate` (11 scripts) = scripted HP set (heal/lower to set phase): `set_hp_rate` column (`id;rate`).
- `Character::CreateGroupEnemy` (27 scripts), `PlacementEnemyNoReactInvincible` (invulnerable cutscene windows).
- Phase/cutscene user-function tokens (column `tokens`, romaji from `sub_*`, boss/battle/phase/event names): `bosschange*`, `bossdefeateventmain/parallel`, `bossarea`, `appear`, `aware`, `barrier`, `break01-04`, `wave`, plus names usable for identity: morihide, genshin, shigurui, jubei, boshitsuki, hyakki, kurama, tokoyo, nureonna, akaname, alchemist, kuramatengu, yoshitsune, yoshitune. 89/110 rows have tokens.
- Phase count is not stored: estimate from distinct HP thresholds + `bosschange` functions. Treat the ranks above as heuristic.

## Caveats
- Arg decoding takes the last 3 constants pushed before the call (decoder from `scratch\dec_a.py`); calls with computed args show `var`.
- Stage names are only those present in the script's string pool; 57 scripts have none.
- Does not resolve which actor the flags target (placement id comes from `Duel::GetBossPlacementID` data, see `boss-fights.md` section 7).
