# Hold MA miss: exact compare (pc/2 Opus, 2026-11-19 3:50 pm EST, human #120730/#120748)

Static RE only (decomp_ro), no game.

- 0x4F54C4 is the generic set-move wrapper (vtable DATA ref 0x4e57448); 0x4F5526 is just the return of set-move
  0x35BC68 at its top. The decision is upstream, in the move's branch/cancel key scan.
- Scanner: FUN 0x20dfc0(this, moveRes = this[0x1d+slot], float t, byte slot), called from 0x47fbf0 (0x47fc2b) with
  t = vtable+0xb0(this, slot) = current anim time (1/60 s units). Callers also 0x236224c, 0x9e4eac.
- Per key (time k = FUN 0x20fd30(key, res)), plain path fires when  t <= k < t + step,  step = [this + 0x40 + slot*4]
  (= 60/fps, Grok #116908). Half-step variant when FUN 0x20e8f8 true: windows [t, t+step/2) and [t+step/2, t+step).
  Range keys use FUN 0x20fc38(t, step) on the same [t, t+step).
- Each frame the window is [t_n, t_n + s_n) but time advances by the NEXT frame's step: t_{n+1} = t_n + s_{n+1}.
  Fixed dt (60 cap, Max120) tiles exactly -> never misses. Uneven dt with s_{n+1} > s_n leaves a gap
  [t_n + s_n, t_{n+1}); a branch key inside it is skipped. Matches kb-118263: 11.82 -> 12.48 jump skips the frame-12
  MA branch, move runs to ~28.5 (player sees heavy swing first). Same scanner for every move -> also explains the
  start-of-combo miss in the reporter video (#120723).
- Fix design (generic, no move ids): detour 0x20dfc0; per (this, slot, moveRes) keep prevEnd = t + step of the last
  call. If same moveRes and prevEnd < t and t - prevEnd < 4.0, call the original with t' = prevEnd and step' = t + step
  - prevEnd (step written to [this+0x40+slot*4] for the call, restored after). Never shrink a window (overlap kept as
  stock). Toggle default off. Live A/B: kb-118263 rig, Tier120 uncapped + CPU load, 16 holds/arm, score exit t60 > 20.
