# CPU100 pass: performance opportunities spotted while naming Unknown_ functions

Listed, not implemented. The share is perf_coverage.py --self (combined Ally+PC share of all samples) plus incl (the PC inclusive view). The "risk" is the risk of changing behaviour.

## u3 share ((rva>>4)%4==3, 98 functions), 2026-10-08

None of these is hot: every function in this share is below 0.001 % self time (max 0x866978, 0.0006 %), and the largest inclusive share is 0x2286b8 at 0.07 %. So these are fps-neutral on their own and only worth doing if a hotter caller makes one of these patterns matter.

- `0x585a74` **SharedReqSetClosedFlagAndFinalize** (self 0.0000 %, incl 0.021 %): its callee 3440F80 spins on a CAS of req+28h, and when no job context is passed it backs off with Sleep(1), which can stall up to a full timer tick (about 1-15.6 ms). Fix: use a short pause-spin then SwitchToThread, or wait on an event or WaitOnAddress; risk med (threading)
- `0x4082b4` **CharacterDispatchAttachmentPoseUpdates** (self 0.0000 %, incl 0.003 %): allocates and queues one 0x58-byte job (JobPushToOwner) per attachment slot, for at most 6 per character per frame, so job allocation and queue overhead likely rivals the CharacterPoseCopyAndSetup work itself. Fix: batch all of a character's slots into one job, or run them inline when the count is small; risk med
- `0x866978` **MissionEntryWithinTimeAndCountLimits** (self 0.0006 %, incl 0.000 %): each call looks up two constant params (float 0xA540, int 0x5B91) from the g_DataMgr+230h table. Its caller 866864 calls it twice per list entry every mission-thread step; fix: read both limits once per step and pass them in, or cache them at data load; risk low
- `0x2d51fc` **PhysicsStepBuildBodyBatches100** (self 0.0001 %, incl 0.000 %): every physics step heap-allocates a 60h-byte batch object for each 100 ready bodies (allocator vfunc +28h) and frees them afterwards, and walks the whole body list to filter ready bodies; fix: keep the batch objects pooled across steps and reuse them; risk low-med
- `0x3634b0` **AudioTrackedSoundsUpdate** (self 0.0000 %, incl 0.000 %): for every tracked sound with an owner it computes a full SqrtfSlowPath distance just to test against 2000/300. It calls the manager getter 363AB8 several times per entry, and it holds mutex +0x2D7F0 for the whole list walk, including the command posts (6A875C/845530). Fix: compare squared distances (4e6/9e4), keep the getter result in a local, and queue the commands to post after unlocking. Risk: low (sqrt and getter changes), med (moving the posts out of the lock).
- `0x16407c` **ObjSetField114Recursive** (self 0.0001 %, incl 0.000 %): always walks the whole part tree (+0x240 children, 3 slots at +0x400), even when o+0x114 already equals v. It is called from per-frame visibility and update paths (PlaceableVisibilityUpdateRange, StageVisibilityUpdateEntries, ObjUpdateJobDispatch). Fix: return early when o+0x114 == v, which is only valid if children can never differ from their parent. Risk: med.
- `0x13087f0` **ScreenSystemSubmitLayers** (self 0.0000 %, incl 0.000 %): each dead weak handle is removed from lists [10..0xB] and [0xD..0xE] with a Memcpy that shifts the rest of the list, so pruning k entries costs O(n*k), up to O(n^2). The temp draw vector also grows through VectorGrowInsert16B one element at a time with no reserve. Fix: compact each list in one erase-remove pass and reserve the temp vector to the sum of both list sizes. Risk: low.
- `0x2732b8` **CharacterTargetTrackFrameUpdate** (self 0.0000 %, incl 0.000 %): per frame it calls the target getter 6181D8(c,1) about 5 times and the threshold lookup 684C04(c,7/9/0x10) several times inside the same comparisons. It also clears 0x156+0x83 bytes and copies a 0xD6-byte snapshot every tick. Fix: fetch the target and the thresholds once into locals. Risk: med (I have not confirmed that those calls have no side effects or state changes between them).
- `0x1c957c` **TextLayoutAppendGlyphOrBreak** (self 0.0000 %, incl 0.000 %): for each appended glyph it can call the font-metric query FE40010 twice with the same (font, size, ch), once for ascent and again for descent when (+0xE103&0xF)==2. It also calls the 1C9E28 predicate up to 3 times before reaching the append. Fix: query the metrics once per glyph and keep the predicate result in a local. Risk: low (gain is small; it only matters for long or rebuilt text).
- `0x494ab8` **BTreeFindKeyBlobA0** (self 0.0000 %, incl 0.000 %): B-tree descent runs the full key compare (u32 +10h, then memcmp of up to [key+98h] bytes) twice per entry, once for the `<0` test and again for the `==0` test; fix: compute the compare result once per entry (and binary-search the up to 18 keys in each node); risk low
- `0x138eb0` **StageVisibilityEntryRuleActive** (self 0.0000 %, incl 0.000 %): each call does three successive sorted-range searches over the static rule table 46BC670..46C01F0 using (e+500h, e+508h, hash). That key never changes for a given entry; fix: cache the resolved rule pointer (or "none") on the entry and only re-run the per-call PlayerCharacterGet/ClearMapGet checks; risk low-med (unsafe if entries change stage/id without invalidating the cache)
- `0x5a6d74` **CachedFlagRefreshIfReady0C** (self 0.0000 %, incl 0.000 %): resolves the same handle o+18h through 12CEEE4 twice on the refresh path; fix: resolve once and reuse the pointer; risk low (minor gain, 9 callers)
- `0x4ec3b0` **LockedCheckInitialized270** (self 0.0000 %, incl 0.000 %): takes a critical section (or virtual lock) only to read one aligned 32-bit field +270h; fix: use an atomic/acquire load and drop the lock; risk med (the lock may be ordering other state that callers rely on)
- `0x3e030` **RenderLayerPruneSortSubmitEntries** (self 0.0000 %, incl 0.000 %): removes dead handles from the l[10..11] and l[13..14] vectors one at a time with a Memcpy shift of the tail inside the scan loop, which is O(n^2) when many entries die together; it also builds a temporary merged 16-byte vector through VectorGrowInsert16B with no reserve on every call. Fix: compact in one remove_if-style pass, and reserve (or keep a persistent scratch vector for) the merged list sized to count(l[12..13]) + count(l[15..16]) + 1; risk low
- `0x1c85fc` **Array20BAppendGrow64** (self 0.0000 %, incl 0.000 %): grows the 20-byte record array by a fixed 64 elements per realloc (12D014), so filling a large stream costs O(n^2) in copies. Fix: grow geometrically (x1.5 or x2, at least +64); risk low (watch allocator size limits)
- `0x6e77fc` **AnimClipFramesToSeconds** (self 0.0000 %, incl 0.000 %): on every call it runs a hash-index probe into g_DataMgr+448h only to read the clip's frame rate (record+10h). It has 32 callers, including AnimLayerSampleClip, which calls it per layer per frame. Fix: cache the rate, or 1/rate, in the anim layer/clip instance when the clip is bound, and multiply instead of divide; risk low
- `0x5e8fbc` **AttachmentsSyncTransformAndFade** (self 0.0000 %, incl 0.000 %): for each attachment it calls the opaque getter 731A78(plVar18) about 10 times, and the compiler cannot CSE these external calls. It also makes 3 separate virtual calls on the owner (vtbl 88h/90h/98h) per entry, although the owner is the same for every entry. Fix: hoist the owner position/rotation/scale reads out of the loop, and call 731A78 once per entry and keep the result in a local; risk low

## u0 share ((rva>>4)%4==0, 114 functions), 2026-10-08

Nothing here is hot in self time: the top function is 0x117940 / 0xfae380 at 0.0006 %. The two biggest inclusive shares are 0xfae380 at 0.48 % and 0x45dcc at 0.23 %. Both are fps-neutral on the GPU-bound Ally.

- `0xfae380` **StageUpdateJobCollisionUnitsPass** (self 0.0006 %, incl 0.48 %): every run builds a temporary {entry, count} vector that grows one element at a time through 1F7DFE4 with no reserve, then sorts it (FA0E40). It then allocates one 48h-byte job per collision entry and calls JobGroupWait twice. While walking the unit map it does an atomic refcount inc/dec on every unit, even units it skips. Fix: give the vector a persistent scratch buffer reserved to the entry count (+560h); batch small entries into fewer jobs; take the refcount only for units that pass the flag tests. Risk: low (vector), med (job batching changes the parallel layout).
- `0x45dcc` **StageObjSetDistanceUnloadUpdate** (self 0.0000 %, incl 0.23 %): for every 80h-byte record, every update, it acquires an object handle (455818), reads ResLinkGetHeaderHash, switches over 9 model hashes and releases the handle. All of that only picks a distance threshold (20000/25000/50000), which is constant per record. Fix: cache threshold^2 in the record when it is created, and skip the handle round-trip. Risk: low (unsafe only if a record's model can change in place).
- `0x5488c` **LayerNodeForwardToChildren** (self 0.0003 %, incl 0.10 %): rescans the whole modifier list (+58h) on every call to find types 0Fh/16h/17h before it forwards to the children. Fix: cache the folded modifier values and mark them dirty when the list changes. Risk: low-med (it depends on where the modifiers are written).
- `0x1a5180` **PropTableResolveLayered** (self 0.0003 %, incl 0.000 %): for every input key it linearly scans the output records accumulated so far (puVar1[0..uVar41]), which is O(n*m) per resolve. Fix: use a small hash or a sorted insert keyed on the u32 id. Risk: low.
- `0x2f3d08` **PropTableReadParamsBatch16** (self 0.0000 %): for each fetched key it linearly scans the request table (param_5 records). Callers are mostly render-node factories, so this is setup time and not per frame. Fix: sort the request table once, or index it by key. Risk: low, and the gain is mainly in load time.
- `0x3fc48` **AtomicBitLockAcquire** (self 0.0000 %, 641 callers): the contended spin re-reads the word with LOCK cmpxchg-style loads and has no PAUSE, and it only yields (Sleep(0)) every 256 spins. Fix: spin on a plain load with _mm_pause, and do the CAS only once the bits are clear. Risk: low (behaviour unchanged, less cache-line ping-pong under contention).
- `0x266a84` / `0x89ab80` **AudioSystemGetStatsLocked / AudioListenerGetAttributes** (self 0.0000 %): each takes the audio-system critical section only to copy a few aligned u32/float fields. Fix: use a seqlock or atomic snapshot, or batch reads per frame. Risk: med (the lock may order these reads against the mixer thread).
- `0x11e784` **EffectInstanceTickFrames** (self 0.0000 %): when more than one 60-Hz frame has elapsed it runs the full EffectSystemUpdate once per elapsed frame (a catch-up loop). At 30 fps every effect instance therefore simulates twice per rendered frame. Fix: none without changing behaviour (a variable-dt update would change the look). Listed only to explain effect CPU cost at low fps. Risk: high.

## u1 share ((rva>>4)%4==1, 99 functions), 2026-10-08

None of these is hot either. The top self-time function is 0x1a6c358 SoundMgrWorkerThreadProc at 0.0005 %; it also has the only real inclusive share in this set (0.91 %, mostly its callees and waits). Every other function is under 0.0004 % self. These fixes are fps-neutral unless a hotter path starts using these patterns.

- `0x1a6c358` **SoundMgrWorkerThreadProc** (self 0.0005 %, incl 0.91 %): on every wake it takes the exclusive SRW lock +0x1B0, then walks about 7 per-type pending lists (+0x30A8, +0x3118, +0x3188, +0x31F8, ...) node by node to promote state-1 entries to state 2 and relink them into the active lists. After that it makes several more passes over the +0x3B8 groups under shared locks. Game threads that create or stop sounds block on +0x1B0 for the whole scan. Fix: have the producers push new entries onto a lock-free or briefly locked intake queue, and have the worker swap that queue out and promote only those entries. Risk: med (threading; the state-1/2 handshake must stay the same).
- `0x8ae6c0` (caller of **AllocatorPair_ReallocWithFallback** 0x12d014, used by **Array24At8_ReserveIfNeeded** 0x1c6a5c) (self 0.0000 %): it grows the 24-byte-element array to exactly the requested count. Callers that reserve n+1 per append therefore realloc and copy on every insert, which is O(n^2). Fix: grow geometrically (max(n, cap*1.5)). Risk: low (watch the memory peak).
- `0x4321d4` **PadInput_UpdateButtonEdges** (self 0.0000 %): for every mapped button, every frame, it FNV-hashes the same 4-byte id three times and probes three separate unordered_maps (held/pressed/released). Each probe throws if the key is missing. Fix: the button ids are small and dense, so keep one array of {held, pressed, released} indexed by id, or at least hash once and reuse the bucket. Risk: low.
- `0x198410` **AxisSlabGrid_QueryRange** (self 0.0003 %, incl 0.0006 %): it scans the X and Z slabs from index 0 until the first slab past the range, although the slabs have uniform width (+0x16B0/+0x16B4) and origin (+0x1660/+0x1668). Fix: compute the first slab as floor((min - origin) / width) and start there. Risk: low (clamp to [0, count)).
- `0x226dd4` **PointDistanceSet_SetPoint** (self 0.0001 %): it takes a sqrt for every point only to store the distance and track the minimum. Fix: if the consumers (AnimLayerEvaluateOutputs, SpatialGridUpdateEntry, ...) only compare distances, store squared distances and take the sqrt of the minimum once. Risk: med (I have not checked whether consumers read the per-point distances +0x50 as linear distances).
- `0x210c54` **Placeable_UpdateDrawDistanceState** (self 0.0001 %, incl 0.0003 %): per placeable per frame it runs two SqrtfSlowPath calls, one for the camera distance and one for the half-extent length, just to test (dist - ext/2) against 0.95 * draw distance. Fix: cache the scaled half-extent length, which only changes with scale, and compare squared values (d^2 vs (0.95*D + r)^2). Risk: low.
- `0x8546dc` **ViewFrameArrays_AllocFromLinearArena** (self 0.0000 %): it makes 5 separate CAS bump allocations on the same shared arena for one view's arrays. Fix: make one CAS for the summed, aligned size and split the block locally. Risk: low (tiny gain; this costs less contention under many render jobs).

Kept as Unknown_ (role not identifiable from the decompile): 0x167c50 (trivial 0x18-byte record ctor, 311 callers, no semantic field use), 0x2002d4 (state machine keyed by ids 0x5692/0x88EF/0xC5A0..., no type context), 0x23bf1c (bounds from a point basis, single unnamed caller), 0x398a54 (2.6 KB, only unnamed callees + GetFrameTimeSeconds), 0x4f9750 (deg->rad/QuatFromToRotation shape update in an unnamed fn-table), 0x556118 (progression/unlock resolve with 55 unnamed callees), 0x59f498 (sums sub-element contributions at a transformed point; element type unknown), 0x7d48d4 (per-index angle-limit weight, unnamed table), 0xf68d8 (1601-case jump table, no context).

## u2 share ((rva>>4)%4==2, 113 functions), 2026-10-08

None of these is hot either. The top self share is 0x1195da0 at 0.0006 %, and the largest inclusive shares are 0xe6fbe0 at 0.037 %, 0xecf24 at 0.015 % and 0x361428 at 0.013 %. They are all fps-neutral on the GPU-bound Ally.

- `0x1195da0` **ObjPartsSubmitFilteredChildren** (self 0.0006 %, incl 0.000 %): for every active table entry it allocates an 8*n pointer array from g_EngineArena (+0x3F5C60, vfunc +0x28), fills it, hands it on and frees it again (vfunc +0x58). Fix: one scratch array per task, sized to the largest n, reused across entries and frames. Risk: low, as long as the callee (+0x10) does not keep the pointer.
- `0x1619ac` **ObjTriggerSyncWithGlobalTable** (self 0.0005 %): for each entry of the object's sorted trigger map it does a full std::map lower_bound in the global map [39C9E38]. Both maps are keyed by the same u32 id, so one merge walk would cost O(n+m) instead of O(n log m). Risk: low.
- `0x2229a4` **SkeletonPoseLocalToModel** (self 0.0003 %, 96 callers): every call allocates a temp (n+1+m)*0x34-byte buffer through the passed allocator (vfunc +0x38) and initialises it. Fix: a per-thread scratch buffer that grows only when needed. Risk: low.
- `0x7d964` **ClothApplyMaxDistanceConstraints** (self 0.0002 %): it calls SqrtfSlowPath(max/d^2) out-of-line for every violated constraint, even though the argument is always positive. Fix: an inline sqrtss, which is correctly rounded and so gives the bit-exact same result. Risk: low.
- `0x5ad9ec` **FrameRenderStateCopy** (self 0.0001 %): copies the 6 KB per-frame state block field by field, as hundreds of scalar dword/byte moves at FrameEnd. Fix: memcpy the contiguous runs, or the whole block when the layout allows. Risk: low, but check for padding or pointer fields that must not be copied.
- `0x361428` **AudioMixActiveVoices** (incl 0.013 %): holds the mixer CRITICAL_SECTION for the whole mix of every active voice (AudioVoiceMixQueuedBuffers), so game-thread voice updates contend with it. Fix: snapshot the active voice list under the lock and mix outside it, with per-voice locks or refcounts. Risk: med (threading).
- `0x162a6c` **SpinLockedRead1C** (self 0.0000 %): takes and releases a Sleep(0)-backoff spin lock just to read one aligned u32 (+0x1C). Fix: an acquire load. Risk: med, because the lock may order other writes that callers rely on.
- `0x362d68` **SortedFlagTableQueryMasked** (self 0.0000 %, 10 callers): takes an exclusive mutex for a read-only binary search. Fix: a shared (SRW) lock, or an RCU-style immutable table. Risk: med.
- `0x12e81e0` **PackedKeyFindFreeSubIndex** (self 0.0000 %): for each candidate sub index it probes the hash table and then linearly scans the whole +0x20 vector, which is O(n^2) in the number of used indices. Fix: keep a next-free counter or a bitset per id. Risk: low-med.
- `0x7433a8` **AudioVoiceLimitStealLowest** (self 0.0000 %): rescans the entire voice list for each voice it steals, O(n*k). Fix: one partial sort (nth_element) by (priority, volume), then stop the lowest k. Risk: low (same choice order when there are no ties).
- `0xaec760` **GlobalRecordFindById_AEC760** (self 0.0000 %, 24 callers): scans all 0x2C58-byte records to the end even after a match, keeping the last one. Fix: break on the first match if ids are unique. Risk: med (changes which record wins on duplicate ids).
- `0x2254a4` **AudioPanComputeSpeakerGains** (self 0.0002 %): every call checks two magic-static init guards (a TLS read plus a compare) for constant +-pi/4 tables. Fix: constexpr tables. Risk: low (tiny gain).

## nf share (Unknown_NotAFunction_* / Unknown_MidFunction_* / *Fragment rows, 49 bogus rows -> 56 leaf functions), 2026-10-08

These rows were sample addresses inside leaf functions (no .pdata) or their cold pieces. perf_coverage now folds such
addresses through `re\out\leaf_ranges.tsv` (`re\scripts_re\leaf_ranges.py`). Everything here is tiny: the hottest function in
this share is MaterialParamNode_NameEquals at 0.015 % self. None of these is worth doing on its own.

- **Measurement fix, not an opportunity**: Ghidra's function sizes had swallowed the next leaf in several places, so a few
  named functions were credited with a neighbour's samples. 0x165060 went to OctreeQueryRecurse, 0x1ce9ec to UiElementWalk,
  0x202df4/0x202e20 to BitmapPoolSlotFreeAtomic, 0x4efafc to TreeLinkDetachableNodesRecursive, 0x699930 to
  EffectNodeUpdateChildren, and 0x117c20 to ResNodeGetPayloadPtr. Each was well under 0.01 %, but any earlier conclusion
  that leaned on those functions' self share was slightly inflated.
- `0x3c774c` **MaterialParamNode_NameEquals** (self 0.0154 %) + `0x3c77b4` **GetNameStrOrEmpty** (0.0020 %): about 20
  param-node classes find a node by name. Each one compares the record hash and then does a byte-by-byte strcmp of the name
  for every candidate. Fix idea: resolve the node once per material or binding and cache the pointer or index, or compare
  the hash only and fall back to strcmp only when the hashes are equal (the hash test is already first, so the gain is the
  repeated lookup itself). Risk: low-med, because the cache must be invalidated when the node list changes.
- `0x202fbc` **PoolUsedBytes128** and `0x4141cc` **RefAddAndQueueToFrameList**: both read an atomic with `lock cmpxchg [x], 0`
  (cmpxchg used as a load). That takes the cache line exclusive on every read. An aligned `mov` (an acquire load) is atomic
  on x64. Fix: use a plain acquire load and keep the CAS only for the update loop. Risk: low. Gain is negligible at the
  current share (<0.001 %), but it removes cache-line ping-pong if these get called from many threads.
- `0x61db84` **FindParamU32ByHashED9DF832** (self ~0 %): every call scans the whole param list for one constant hash.
  Fix: cache the entry pointer per list at load time. Risk: low.
- `0x12ee38` / `0x12f824` / `0x19ed9c` / `0x202df4` **AllocatorOwnsPtr\***: each level of the allocator stack tests its
  own range and on a miss makes a virtual call to the parent. A free that misses walks the whole chain of vcalls. Fix: one
  sorted range table across all allocators. Risk: med (allocator plumbing). The share is ~0, so this is not worth it now.
- `0x58b894` **MaskedCopyRecordFieldToArray** (0.0010 %) / `0x58b9b4` (B twin): loops over every index below the count and
  tests one mask bit per iteration. Fix: iterate the set bits with tzcnt. Risk: low. Gain is tiny.
- `0xde3058` **HashMixU32**: about 20 byte-identical copies sit at 0xDE3058..0xDE3350, a sign that identical-code folding
  was off. This costs code size and i-cache only, not fps. There is nothing to do game-side.
