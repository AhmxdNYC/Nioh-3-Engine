## 1. Routes (what the add-on does per route)
- **R** (59): `MissionRequestById(id, u8 [[47514D0]+8]+10h, 0, params{101h,1000000h,10100h,0,0,0} aligned 16)` = the shrine replay
  confirm (session note s.1), or R-a = `MenuOpenMissionReplay(0,0,6)`. Gate: `MissionClearedGetSlot(db,id)` (702B64) = 1 on this journey.
- **H**: R plus clearing bit 0x4000 of record +0x40 for the replay, restored on exit (built in 1.7.40).
- **D**: the same R-b call on an unlisted record. Refused unless 702B64 reads the record cleared on this journey, so every clear/flag
  write its script does is a repeat (as with R). Unverified: whether these master-duel scripts run from a replay request (`+14` = 2),
  where they return to, and whether 702B64 tracks them (R-15 / verify_all).
- **E0 / E1**: s.4.
- **NG+ / cycles**: every route runs at the current journey (slot byte `[[47514D0]+8]+10h`); there is no per-cycle picker. Picture
  Scroll kinds (normal / Shogun / Enlightened / Nioh x2) are separate scroll items (s.4).
- **DLC (Keian, web: "Hell Rising")**: 9 DLC bosses, all R (Anazawa Morihide, Mori Gentatsu, Yamada Shinryuken, Giant Toad, Kanai Hanbei,
  Kawara Jurobei, Kumagai Naoyoshi, Marubashi Chuya, Yagyu Jubei); Tesso is field-only (0x4431).
- **Hell / Crucible variants**: `optional-crucible-story` missions (Crucible Tour, Beast of the Underworld, Solitary Blade, Guardian of

## 2. Why 29 bosses have no route (proven from data)
1. **Field only (19)**: every boss record (+0x9C bit 4) of the boss's char ids sits in an `internal-stage` mission's enemy table. Those
   21 records are the open-field regions themselves (`CHxx_WORLD_*` tables, 150-700 records each, e.g. 0x14B9 Sengoku region 4, 0x1BA2
   Heian region 2, 0xC502 Edo 2). There is no standalone record to replay; R-b of the region id reloads the whole region; re-placing a
   beaten field boss needs its field defeat flag cleared = a story-flag write, which the design forbids (design s.6); and E1 cannot host
   them (s.3). Tesso, Ninja Yoki, Blood-Spurting Ogin, Gaki Chief, Yoki, Nuppeppo, Yasha, One-eyed Oni, Gaki, Aggrieved Warrior, Waira,
   Tsurara-Onna, Enki, Kyokotsu, All-Seeing Mage, Green Shadow's Blade, Karasu Tengu, Usui Sadamitsu, Yamainu.
2. **No boss record at all (7)**: the char id is known (`boss-names.csv`) but no shipped enemy table holds it with bit 4: Daidara Bocchi
   (only a regular record in field 0xF722), Raiju (regular/wave records only), Demon Slayer, Ishikawa Goemon, Shishido Kagetoshi, Taigen
   Sessai, Takashima Shuhan (no record in the 120 mission tables: scripted spawn or a char id we do not map; unverified).
3. **No data (3)**: Crucible Wraith, Hattori Takeo, Okiku: online names with no char id and no boss-master row.

The web mission names of all 29 stay in `unverified`. The cross-check calls several of them sub-mission bosses; in Nioh 3 sub missions are
open-field quests, i.e. case 1.

## 3. Why E1 (a patched carrier record) cannot host a story or field boss
Design s.5.3 assumed Emaki record `+0x0C` = mission id and `+0x10` = the boss placement. The data says otherwise:
- The Emaki table is a shipped LFM file (`archive_03\70\14FB3450...`, 20 records x 0x34, byte-identical to the live L1 dump). `+0x0C`,
  `+0x10`, `+0x14` are ids in the 17,000,0xx range: `+0x0C` and `+0x10` are rows of **mission 0xCC96's own +0x6C table**
  (`archive_03\6A\D9BEDC41...`, 40 x 0xA4, file id 0x107E5); `+0x14` is a row of its `+0x60` wave-box table (`87\9AB5DD31...`, names
  `HYAKKI_WB_START_<area>`). `EmakiMissionRequest` copies `+0x0C` into queue slot `+0xC` (start point, 10DBFDD).
- `PlacementBuild` 0x1C1E470 iterates exactly that `+0x6C` table of the running mission (1C1E524: `[[set+128h]+6Ch]` -> 1C17B78),
  skips rows with `+0xC == 0`, and under mission 0xCC96 keeps only the row whose id equals `EmakiRecordGet(byte)+0x10`
  (1C1E5AB..1C1E5E4). The kept rows are gadgets of kind 907/909 (wave start), not enemies.
- Mission 0xCC96's enemy table (`+0x54`, file 0x132B1 `9E\6A76F...`) is **empty**: the scroll's enemies come from the wave box.
- Story and field bosses are 0x138 records in *other* missions' `+0x54` tables, which are never loaded under 0xCC96.

So writing a story-boss placement into `+0x10` spawns nothing: a record-patch E1 for named bosses is impossible without new wave data.
What remains valid is the design's alternative: **redirect a carrier's map entry to another of the 20 records** (s.4).

  snapshot + CRC, restored when the scroll mission ends or after a 30 s timeout. `EmakiRecordGet` re-resolves through the map for the
  whole mission, so the patch must live until exit (design s.1). Item consumption on use (Q6) is open.
- No E row names a boss: which yokai a wave ends with is in the wave data (not decoded). verify_all logs the HP-bar placement per record.
