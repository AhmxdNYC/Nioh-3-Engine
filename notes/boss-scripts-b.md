# Boss scripts, rows 53-104 of boss-fights-table.csv (deep decode, 2026-10-08)

Static only. Data: `notes\boss-scripts-b.csv` (52 rows: script, imports, calls_with_args, constants, candidate_boss_selector). Decoder was a throwaway script (not committed); format per boss-fights.md section 7 with these corrections/additions found here:
- Name table entry = `{u16 nameLen, u32 hash, name\0}`; the first name is `umud::yield` (hash bytes 9c 1d 86 75 look like a leading `u`). Symbol table `{nameIdx(0-based), id, kind}`; **a call operand is the symbol `id`, name = names[byid[id]]** (0-based; 1-based gives nonsense).
- Code start = first offset after the UTF-8 string pool (strings `{u16 len, bytes, 0}`, pool ends at the user-function name strings) from which the stream decodes to EOF AND all call/function-marker ids resolve. It can be odd/even; the earlier "even only" rule fails for 1 of 52 (B023D29AFD54).
- **Opcode 0x2d = push float32 (4-byte operand)**, not operand-less. `0x2f u16` = push u16 (index; not a symbol id, targets of `Script::Create` stay unresolved). 0x27 = return value.
- `script_main` (function marker) is the mission entry: `Mission::WaitUpdateSetup`, then `Script::Create` for each sub_event_* coroutine, then `Mission::EndLoop`. ~160 other functions in each script are the shared library (same names in >=26 of 52 scripts: WaitPlayerPrepareDuel*, DuelCommonFlow, DuelCommonFlowAnyRange, CreateClearGadget*, Wait_*, ...).

## Findings
1. **The shared duel flow does not receive the boss id.** `Function::DuelCommonFlow(AnyRange)` calls `Duel::GetBossPlacementID()` and `Duel::IsAliveBoss()` with NO arguments, passes the result to `Mission::BossBattleMode(v)` and `Function::CreateClearGadgetBossPosition(13, v)`. So for flow-based scripts the boss comes from the engine (stage/mission data keyed by `Mission::GetMissionID`), not from the script. Only call-site args from `script_main` are two floats (range): B023CC05F9E5 `DuelCommonFlowAnyRange(4500.0)` then `(680.0)` (S01_SEN_04_SYUKUBA); CFB8ECB9CBF1 `(10000.0)` then `(400.0)` (S02_HEI_01_KURAMA). BFC230194A06 / A96CE28F8E68 / E7923507DECC (S00_EDO_ALL) use `Function::TeacherDuelCommonFlow()` (no args) from script_main or as a library body.
2. **Most boss scripts name the boss directly (28 of 52 pass an integer constant to `Mission::BossBattleMode`).** The constant is a placement/actor id (same id space as `Character::Create`, `Character::IsAlive`, `Character::IsEnterPlacementBoxOne`), and the same constant is reused as arg 2 of `Function::CreateClearGadgetBossPosition(10|11|12, id)` (the first arg is the gadget slot). Example: C65DE6D9C736 `BossBattleMode(84220)` + `CreateClearGadgetBossPosition(10,84220)`. Ids are scaled by stage family (5-6 digit S01/S02, 7-digit S03/S04, 7-8 digit DLC), matching notes\boss-fights.md section 7.
3. **9 scripts expose it through a per-script getter function** returning a constant (`boss_pl_enemy_id`, `boss_id`, `yougashidou_boss_pl_enemy_id`, `get_middle_boss_*_pl_enemy_id`, `jumping_gaki*_pl_enemy_id`), e.g. E00A59553306 `boss_pl_enemy_id()=563857`, AF695E47DE3C 117731, 6F987ACEDA8F 102544, 8008F3E2B14D 65092, 123ABCEA0B98 4022765, 48C62C56A110 206387. Same id space; `tokoyo_enemy_id`/`coop_pl_npc_id` getters are the Tokoyo/coop variants (npc ids are small, e.g. 50, 140, 162).
4. **6 scripts pass a variable** (`BossBattleMode(v1.1)` / `v2.4` etc.): id comes from a function parameter or `Mission::GetTempValue`; the caller's constant is in the CSV `calls_with_args` as `vK.I=value` when a constant store was seen in-function (8EDB00EEC40D: `v1.1=335093`), otherwise unresolved (3F962263B759, 0CA8409CACB7, B023D29AFD54, 2DB4694D793C).
5. Multi-boss scripts (wave/Emaki battles) call BossBattleMode with several constants in one function (24A263DA1592: 1259657/1256771/1259130; 845492A9A27A: 1278948/1278459/1276276; 1EADF481BCCA; B2074F87F0F2; 5A3A552EA629 597242/594637; 5DDCEF297989 4108934/4105770). Final boss is the one also passed to `CreateClearGadgetBossPosition` (or last). F54D0C2234EF has two bosses (masakage 94568, shingen 96416; `BossDefeatEventParallel(96416)` marks shingen last).
6. 8 scripts have no boss constant at all (A47086B78FCD tutorial/training, D2DF2627F6F3 mission-end only, F02A826143C9, 6128FD5B8530, B6C6854EBF81, 5F2E0518FFC8, 057875E8B246, D309DF60D428): they only import the name or use engine-side boss (check their `Duel::GetBossPlacementID` use = shared flow, or coop/Tokoyo scripts). Treat as flow/engine-selected.
7. Per-script values that differ and could select the boss: (a) BossBattleMode constant, (b) CreateClearGadgetBossPosition arg 2, (c) boss getter return, (d) DuelCommonFlowAnyRange float range, (e) `Mission::GetMissionID` (called inside shared flow; engine value), (f) stage ids in the pool (`S0x_*`), (g) `Mission::IsMissionFlag/SetMissionFlag` constants (progress flags; listed in CSV when present), (h) user-function name tokens (goganki, masakage, shingen, kamaitachi, yougashidou, nureonna, ...) which also name the boss. The name-table hashes are identical across scripts (same library), so they do not discriminate.
8. 32-bit constants like `Gadget::SetReplacementStatus(0x........, n)`, `Gadget::SetDoorControlAbsoluteClose(1302396295)` are gadget/object hashes; none matched `kidshash.py` over the script's own pool strings and names (0 of all), so they are hashes of stage object names not present in the script.

## Practical use for a rematch tool
Hook `Mission::BossBattleMode` (0x23A2DCC) and `Character::Create` (0x1180740) in-game: the first arg to BossBattleMode IS the boss placement id (constant in 28 scripts, engine-supplied in the flow scripts). Matching it against the CSV constants tells which script/fight is active; for flow scripts the id only appears at runtime.
